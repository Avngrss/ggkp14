# Обзор проекта: редизайн ggkp14.by

## Цель проекта

Создать современный UI-редизайн сайта ГУЗ «Гомельская городская клиническая поликлиника №14» (https://ggkp14.by/) с сохранением исходной структуры, иерархии страниц, логики навигации, порядка контента и пользовательских сценариев. Итоговый результат — статический frontend-демо и подготовленная структура WordPress-темы.

## Исходный сайт

- **URL:** https://ggkp14.by/
- **Тип:** официальный сайт государственного медицинского учреждения (WordPress)
- **Язык:** русский
- **Аудитория:** пациенты, родственники, абитуриенты, сотрудники, граждане, обращающиеся в учреждение

## Что необходимо сохранить

- Порядок и состав основных секций главной страницы
- Структуру навигации (верхняя панель, главное меню, быстрые ссылки)
- Все URL-адреса и логику переходов между разделами
- Контактную информацию (телефоны, адрес, email, режим работы)
- Блок структурных подразделений с полным перечнем отделений
- Ленту последних новостей и категорию «Новости»
- Блок полезных ссылок (государственные и медицинские ресурсы)
- Боковую панель (поиск, время работы, полезные ссылки)
- Функциональность: запись к врачу, электронные обращения, заказ выписки, диспансеризация и др.
- Версию для слабовидящих (как функциональное требование)
- Многоязычность (флаг RU, потенциально другие языки)

## Что можно и нужно переработать

- Визуальный стиль (цвета, типографика, отступы, тени, скругления)
- Компоновку hero-слайдера и карточек быстрых услуг
- Карточки подразделений и новостей
- Боковые виджеты и их визуальное оформление
- Мобильное меню и адаптивное поведение
- Иконки и декоративные элементы
- Качество типографической иерархии и читаемости
- Доступность (контраст, focus states, семантика)

## Правила работы

1. Вся работа выполняется агентом через Cursor — пользователь не создаёт файлы, папки и документацию вручную.
2. Исходный сайт используется только для понимания структуры, контента и поведения — CSS и UI не копируются.
3. Сначала — аудит и планирование, затем — статический frontend, затем — WordPress-тема.
4. Каждый этап завершается верификацией по чеклисту.
5. Коммиты и деплой — только по явному запросу пользователя.

## Ожидаемые итоговые deliverables

| Этап | Результат |
|------|-----------|
| Stage 1 (текущий) | Структура проекта, аудит, планы, WordPress mapping |
| Stage 2 | UI Kit (CSS variables, базовые компоненты) |
| Stage 3 | Статический HTML/CSS/JS demo главной страницы |
| Stage 4 | Аудит и редизain внутренних страниц |
| Stage 5 | WordPress-тема с шаблонами и ACF-полями |
| Stage 6 | Инструкции по установке и наполнению для администратора |
